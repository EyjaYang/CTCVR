# Ali-CCP 数据集说明

数据目录：`src/data/`。整理日期：2026-11-10。

数据来源为天池的 [Ali-CCP: Alibaba Click and Conversion Prediction](https://tianchi.aliyun.com/dataset/408)，用于点击与转化预测。本文以本地原始文件为准，说明存储结构、关联方式和解析规则；字段语义另参考 [NVIDIA Merlin 的 Ali-CCP 数据定义](https://github.com/NVIDIA-Merlin/models/blob/main/merlin/datasets/ecommerce/aliccp/dataset.py)。天池页面正文依赖动态加载，本次未取得完整正文，因此不将其他项目的预处理结果视为本地原始数据。

## 先用一条真实样本读懂两张表

**一条样本描述一次曝光：把一个商品展示给一个用户，并记录后来是否点击、是否转化。**

下面使用本地训练集的真实记录：`sample_skeleton_train.csv` 第 **24,233** 行，以及 `common_features_train.csv` 第 **7,132** 行。两条记录关联后可以读成：

> 在样本 24233 这次曝光中，用户 431970 看到了商品 4216225。用户点击了，但没有转化。模型可以使用该用户的画像、历史行为，以及本次展示的商品和位置特征，学习预测点击、转化的概率。

### 第一步：样本表记录“这次展示了什么，结果怎样”

原始行的外层结构如下，最后一列暂用说明文字代替：

```text
24233,1,0,0e71ffdbee24754a,9,<这次曝光的9个特征条目>
```

| 实际内容 | 对这条样本的解释 |
| --- | --- |
| `24233` | 本次曝光的样本编号 |
| `1` | 点击标签：用户点击了 |
| `0` | 转化标签：用户没有转化 |
| `0e71ffdbee24754a` | 去公共表查找用户资料时使用的关联键 |
| `9` | 最后一列包含 9 个特征条目 |

**用户 ID 不在前五列里。** 需要先根据关联键找到公共记录，才能读到该记录中的用户 ID。

最后一列中的 9 个条目，拆开后完整如下：

| `field_id`（特征类型） | `feature_id`（具体编码） | `value`（权重） | 解释 |
| --- | --- | ---: | --- |
| `210` | `9066325` | 1.0 | 商品的一个意图节点 |
| `207` | `8400999` | 1.0 | 商品所属店铺 |
| `206` | `8319816` | 1.0 | 商品所属类目 |
| `205` | `4216225` | 1.0 | 本次展示的商品 ID |
| `301` | `9351666` | 1.0 | 本次展示的位置编码 |
| `210` | `9092334` | 1.0 | 商品的另一个意图节点 |
| `210` | `9055430` | 1.0 | 商品的另一个意图节点 |
| `210` | `9069973` | 1.0 | 商品的另一个意图节点 |
| `210` | `9073171` | 1.0 | 商品的另一个意图节点 |

以商品 ID 这一项为例，文件中的实际编码是 `205\x024216225\x031.0`。加上空格和方括号来帮助辨认，就是：

```text
205  [\x02]  4216225  [\x03]  1.0
 ↑               ↑            ↑
商品ID这一类型   具体商品编码    该条目的权重
```

方括号和空格仅用于展示。相邻两个条目之间再用 `\x01` 连接。

这里 `205` 是“商品 ID”这一特征类型的编号，`4216225` 才是本条样本中的具体商品编码。权重 `1.0` 表示这个特征条目的取值；是否点击由行首的 `click` 标签表达。

### 第二步：拿关联键去公共表找到“这个用户的资料”

在 `common_features_train.csv` 第 7,132 行，可以找到：

```text
0e71ffdbee24754a,86,<这份公共资料的86个特征条目>
```

两个文件里的 `0e71ffdbee24754a` 完全相同，所以把这份公共资料接到样本 24233 上。公共行的 86 个条目按类型分组如下，长列表仅展示部分内容：

| `field_id` | 内容 | 这条公共记录中的实际值 | 条目数 |
| --- | --- | --- | ---: |
| `101` | 用户 ID | `431970`，权重 1.0 | 1 |
| `121` | 用户画像类别 | `3438658`，权重 1.0 | 1 |
| `122` | 用户画像分组 | `3438757`，权重 1.0 | 1 |
| `124` | 性别类别 | `3438768`，权重 1.0 | 1 |
| `125` | 年龄类别 | `3438774`，权重 1.0 | 1 |
| `127` | 消费水平类别 | `3438782`，权重 1.0 | 1 |
| `128` | 在职状态类别 | `3864885`，权重 1.0 | 1 |
| `129` | 地理信息类别 | `3864888`，权重 1.0 | 1 |
| `109_14` | 历史类目特征 | 如 `(449601, 1.38629)`、`(449452, 0.69315)` | 7 |
| `110_14` | 历史店铺特征 | 如 `(3065596, 0.69315)`、`(883423, 1.09861)` | 11 |
| `127_14` | 历史品牌特征 | 如 `(3467303, 0.69315)`、`(3851261, 1.09861)` | 5 |
| `150_14` | 历史意图特征 | 如 `(3871927, 0.55962)`、`(3908800, 0.22314)` | 55 |

条目总数为 `8 + 7 + 11 + 5 + 55 = 86`。历史特征中括号的含义是 **`(具体特征编码, 对应权重)`**。

注意，年龄的 `3438774` 是类别编码，不能读成年龄数值；历史类目里的 `1.38629` 是数据提供的权重，也不能直接说成浏览了 1.38629 次。没有相应映射或变换说明时，应保留这些编码和权重。

### 第三步：把两边接起来，形成一条训练样本

这条样本关联后的内容，可以用下面的可读结构表达。这里只展开部分历史条目，实际关联应保留全部条目。

```text
样本编号：24233

输入 X：
  来自公共表：
    用户 ID = 431970
    年龄类别 = 3438774
    历史类目 = [(449601, 1.38629), (449452, 0.69315), ...]  共 7 项
    历史店铺 = [(3065596, 0.69315), (883423, 1.09861), ...] 共 11 项
    历史品牌 = [(3467303, 0.69315), (3851261, 1.09861), ...] 共 5 项
    历史意图 = [(3871927, 0.55962), (3908800, 0.22314), ...] 共 55 项
    以及其余用户画像特征

  来自样本表：
    商品 ID = 4216225
    商品类目 = 8319816
    店铺 ID = 8400999
    展示位置 = 9351666
    商品意图 = [9066325, 9092334, 9055430, 9069973, 9073171]
    以上 9 个条目的权重均为 1.0

监督标签 y：
  click = 1
  conversion = 0
```

所以模型学习的问题可以表述为：“给定这些用户、历史行为、商品和展示位置特征，这次曝光会不会被点击，会不会发生转化？”标签是训练时提供的答案，不应放进输入特征。

本例共有 **`86 + 9 = 95` 个特征条目，分属 17 个特征域**。前面说的“23 个特征域”是整个数据集使用的域字典；单条样本可以缺少某些域，也可以在同一域下有多个条目。本例的 `210` 有 5 项，因此“95 个条目”不等于“95 个域”，也不代表已经得到一个固定长度为 95 的模型向量；后续还需要选择多值聚合、Embedding 等输入编码方式。

### 为什么公共特征要单独存一份？

同一训练文件中还有另一条真实记录：

| 样本编号 | 公共特征关联键 | 公共表中的用户 ID | 本次商品 ID | 点击 / 转化 |
| --- | --- | --- | --- | --- |
| `24233` | `0e71ffdbee24754a` | `431970` | `4216225` | `1 / 0` |
| `24239` | `0e71ffdbee24754a` | `431970` | `4699667` | `0 / 0` |

两次曝光展示了不同商品，标签也不同，但复用了同一份 86 条公共特征。将用户资料单独保存，就可以在样本表中只放一个关联键。

这几个编号各有用途：**`24233` 标识本次样本；`0e71ffdbee24754a` 用来查公共资料；`431970` 标识用户；`4216225` 标识本次商品。**

```text
└── sample_skeleton_test.csv       # 测试集曝光样本、标签及样本侧特征
```

每个压缩包包含对应 split 的两张表，直接解压到当前数据目录。`sample_skeleton` 是样本表，`common_features` 是公共特征表，两者通过 `common_feature_id` 关联。同一份公共特征可被多条曝光样本复用，避免在每条样本中重复存储大量用户历史特征。

```text
sample_skeleton_train.common_feature_id → common_features_train.common_feature_id
sample_skeleton_test.common_feature_id  → common_features_test.common_feature_id

一条完整样本 = 标签 + 样本侧 feature_list + 对应公共 feature_list
```

按同一 split 的键关联，不按文件行号拼接。`common_feature_id` 是关联键，不等同于 `101` 域中的用户 ID，也不应直接当作业务特征。

## 3. 两张表的行格式

四个 CSV 均无表头。外层由英文逗号分列，末列内部是包含控制字符的稀疏特征串。

### 3.1 曝光样本表：`sample_skeleton_{train,test}.csv`

```text
sample_id,click,conversion,common_feature_id,feature_num,feature_list
```

| 列位置（从 1 开始） | 名称 | 建议读取类型 | 含义 |
| --- | --- | --- | --- |
| 1 | `sample_id` | 字符串 | 样本标识；无需将其作为连续数值输入模型 |
| 2 | `click` | 整数 | 点击标签，0/1 |
| 3 | `conversion` | 整数 | 转化标签，0/1 |
| 4 | `common_feature_id` | 字符串 | 对应 split 公共特征表的关联键 |
| 5 | `feature_num` | 整数 | 本行 `feature_list` 的特征条目数，不含关联后的公共特征 |
| 6 | `feature_list` | 原始字符串或 bytes | 商品、上下文及用户与商品组合等样本侧特征 |

`feature_num` 统计的是特征条目数，不是不同 `field_id` 的数量。`sample_id` 与关联键均建议原样保留。

### 3.2 公共特征表：`common_features_{train,test}.csv`

```text
common_feature_id,feature_num,feature_list
```

| 列位置（从 1 开始） | 名称 | 建议读取类型 | 含义 |
| --- | --- | --- | --- |
| 1 | `common_feature_id` | 字符串 | 公共特征记录的关联键；本地样例为十六进制形式的字符串 |
| 2 | `feature_num` | 整数 | 本行公共特征的条目数 |
| 3 | `feature_list` | 原始字符串或 bytes | 用户标识、画像和历史行为特征 |

## 4. 稀疏特征编码

末列的结构为：

```text
field_id\x02feature_id\x03value\x01field_id\x02feature_id\x03value...
```

| 分隔符 | 十六进制字节 | 用途 |
| --- | --- | --- |
| `,` | `0x2C` | 外层列分隔 |
| `\x01` | `0x01` | 分隔特征条目 |
| `\x02` | `0x02` | 分隔 `field_id` 与 `feature_id` |
| `\x03` | `0x03` | 分隔 `feature_id` 与 `value` |

上面的 `\x01` 等是控制字符的可见转义写法。实际文件存储的是单个控制字节，而不是反斜杠、字母和数字组成的文本。

- `field_id`：特征域，如 `101`、`205`、`109_14`，应作为字符串读取。
- `feature_id`：域内的离散特征标识，建议以 `(field_id, feature_id)` 为编码键，避免跨域混淆。
- `value`：浮点形式的数值或权重。不要仅保留 ID 而默认丢弃该值，也不要把所有域的值都解释为次数。

同一域可以出现多次，尤其是历史行为域；本地样本中的商品意图域 `210` 也存在多值。应保留为列表或其他多值表示；直接写成 `features[field_id] = feature_id` 会覆盖先前的条目。历史行为特征在这里以稀疏条目存储，不能仅凭文件中的排列顺序认定其为带时间戳的行为序列。

本地训练公共表第一行开头的真实示例（仅展示前 3 个条目）：

```text
84dceed2e3a667f8,343,101\x0231319\x031.0\x01125\x023438774\x031.0\x01126\x023438779\x031.0...
```

这表示关联键为 `84dceed2e3a667f8`，本行共 343 个特征条目；第一个条目为 `(field_id="101", feature_id="31319", value=1.0)`。

## 6. 标签与任务

| 任务 | 概率含义 | 数据使用方式 |
| --- | --- | --- |
| CTR | `P(click=1 | exposure, x)` | 在全部曝光上预测 `click` |
| CVR | `P(conversion=1 | click=1, x)` | 常规监督训练在点击样本上预测 `conversion` |
| CTCVR | `P(click=1, conversion=1 | exposure, x)` | 在曝光空间建模点击并转化的概率 |

点击到转化链路期望满足 `conversion=1 ⇒ click=1`，但应先检查原始标签是否符合这一约束，并显式处理异常组合。不能把非点击样本的 `conversion=0` 直接解释为点击后的 CVR 负样本。链路一致时，`pCTCVR = pCTR × pCVR`。

本地原始分包只有 train/test，没有单独的验证集文件；需要从训练集自行划分验证集，并记录划分规则。测试集的样本表也含标签列。

## 7. 最小解析示例

下面的示例仅读取训练样本表第一行，不会把整个数据集装入内存。以项目根目录作为工作目录运行。

```python
from collections import defaultdict
from pathlib import Path

DATA_DIR = Path("src/data")


def parse_features(blob: bytes):
    features = defaultdict(list)
    if not blob:
        return features
    for entry in blob.split(b"\x01"):
        field_id, rest = entry.split(b"\x02", 1)
        feature_id, value = rest.split(b"\x03", 1)
        features[field_id.decode("ascii")].append(
            (feature_id.decode("ascii"), float(value))
        )
    return features


with (DATA_DIR / "sample_skeleton_train.csv").open("rb") as stream:
    row = stream.readline().rstrip(b"\r\n")
    sample_id, click, conversion, common_id, feature_num, blob = row.split(b",", 5)
    features = parse_features(blob)
    assert sum(map(len, features.values())) == int(feature_num)
    print(sample_id.decode(), int(click), int(conversion), common_id.decode())
```

全量处理时建议按块读取样本表，并采用磁盘键值索引、分桶关联或分片列式文件保存中间结果。将全部公共特征解析为 Python 字典会明显放大内存占用；直接读取全部 CSV 或把公共特征复制到每条样本，也会增加存储与内存成本。特征词表和归一化统计应在训练部分拟合，再应用于验证集和测试集。
